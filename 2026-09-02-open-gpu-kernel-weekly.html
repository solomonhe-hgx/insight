本周新增 MMU Issues

Issue #1329 - Turing Suspend 死锁: kgmmuInvalidateTlb 在 BAR2 拆卸后自旋 (NEW)

HIGH

问题: Turing 架构 GPU 在 suspend 过程中，nv_drm_mmap 在 BAR2 已被拆卸后仍然自旋调用 kgmmuInvalidateTlb，导致死锁。这是 MMU TLB 失效与电源管理路径之间的竞态条件。

日期: 2026-08-31 | GitHub Issue #1329

技术分析

根因是 suspend 路径中的时序问题: BAR2 内存区域已被 unmap/teardown，但 nv_drm_mmap 仍然尝试通过 kgmmuInvalidateTlb 刷新 MMU TLB 条目。这导致对已释放资源的访问，形成死锁。该问题与 #1148 (Ampere NVLink suspend 累积) 类似，都是 suspend/resume 路径中的状态管理 bug。

影响范围

影响所有 Turing 架构 GPU (RTX 20 系列 / TU102-TU117)。在多 GPU 或频繁 suspend/resume 场景中更容易触发。与 #1148 一起表明 NVIDIA 开源驱动的电源管理路径存在系统性问题。

Issue #1324 - dma-buf 导出返回 IOMMU 翻译下的未映射 BAR 地址 (NEW)

HIGH

问题: 在 IOMMU 翻译环境下，dma-buf 导出操作返回的 BAR 地址未被正确映射。这导致使用 dma-buf 进行 GPU 间内存共享时出现访问失败。

日期: 2026-08-27 | GitHub Issue #1324

技术分析

当系统启用 IOMMU 时，设备看到的物理地址与 CPU 地址不同 (需要 IOMMU 翻译)。dma-buf 导出时返回的是 BAR 空间的设备地址，但如果 IOMMU 翻译未正确配置，这些地址对导入方来说是无效的。这与 PR #1301 (DMA address limit check) 和 PR #1269 (DMA submap alignment on 64K pages) 属于同一类 DMA/IOMMU 地址翻译问题族。
