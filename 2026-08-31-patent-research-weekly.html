NVIDIA 通信 / MMU / Memory 专利

多芯粒处理器架构中的 MMU 同步 (Synchronizing Memory Management Units in Multi-Dielet Processor Architectures)

US20260079849A1 2025-11-21 申请 | 2026-03-19 公开
核心创新: 在多 chiplet GPU 架构中协调跨 die 的内存操作。指定一个主 die 的翻译单元负责序列化所有 die 的 bind 请求,实现跨芯粒的 TLB 同步、地址翻译服务 (ATS) 路由和故障上报聚合。
技术实现:
  • Bind 序列化: 主 die 处理来自所有 die 的 bind 请求,次级 die 将本地请求转发至主 die,保持 bind table 全局同步
  • TLB 无效化: 无效化请求路由到主 die,由主 die 广播更新到所有 die,确保同时清除过期的翻译条目
  • ATS 路由: 任何 die 生成的地址翻译服务请求被转发到具有活跃 chip-to-chip 接口的指定次级 die,与系统 MMU 通信
  • 故障上报聚合: 本地检测到的内存访问违规转发到主 die,由主 die 聚合后上报给主机处理器
影响分析: 该专利直接解决 NVIDIA Blackwell/Rubin 多 chiplet GPU 的 MMU 一致性难题。在 GB200 NVL72 等大规模多 die 系统中,跨 die 的地址翻译同步是保证内存一致性的关键。该方案通过主从架构简化了同步协议,降低了 TLB miss 的延迟开销,对 UVM (统一虚拟内存) 在多 die 间的透明访问至关重要。
来源: Google Patents - US20260079849A1

虚拟机系统中的快速安全内存地址翻译 (Fast and Secure Memory Address Translation in a VM Computing System)

WO2026136182A1 2025-12 申请 | 2026-06 公开
核心创新: 在 GPU 内存管理子系统中集成虚拟内存管理单元 (vMMU),通过在高速片上 SRAM 中维护三个位掩码 (段映射、有效性、安全状态),将地址翻译所需的内存读取减少到约 5 次,同时支持机密计算的安全隔离。
技术实现:
  • vMMU 集成: 将虚拟内存管理单元直接嵌入 GPU 内存管理子系统,减少页表遍历的层级
  • 三 bitmask 架构: 使用 SRAM 存储段映射 bitmask、访问有效性 bitmask 和全局安全状态 bitmask,实现快速翻译查找
  • 安全计算隔离: 通过评估 bitmask 执行机密/安全计算策略,确保不同租户环境间的严格隔离
  • 5 次读取优化: 相比传统多级页表遍历 (通常需 4-7 次内存访问),该方案将读取次数稳定控制在约 5 次
影响分析: 该专利对 NVIDIA 的机密计算 (Confidential Computing) 和 GPU 虚拟化 (MIG/vGPU) 场景至关重要。在多租户 GPU 云环境中,地址翻译的安全性和性能直接影响隔离质量和吞吐量。该方案为 Blackwell 架构的机密计算功能提供了硬件级安全翻译基础。
来源: Patsnap - WO2026136182A1 | Justia Patents

多队列 AI 数据传输系统 (Multi-Queue AI Data Transfer System)

NVIDIA 2025 2025-08-29 申请 | 2026-07-23 公开
核心创新: 通过将数据分割为多个片段并通过独立通道并行路由,GPU 在后续片段到达之前就开始处理先到达的数据片段,消除传统方案中等待完整数据集到达导致的 GPU 空闲期。
技术实现:
  • 并行路由: 数据被分割为多个片段,每个片段通过独立的通信通道传输
  • 并发执行: 处理单元在早期片段到达时即开始计算,无需等待所有通道完成传输
  • 自动化配置: 架构自动在生产者和消费者代码组之间建立并行通道,无需手动重写软件
  • 广泛适用: 支持芯片内部传输和跨节点集群通信,加速机器学习工作负载
影响分析: 该专利实现了计算与通信的深度重叠 (compute-communication overlap),是提升大规模 GPU 集群利用率的关键技术。在 LLM 训练的 AllReduce/AllGather 操作中,该机制可显著减少通信等待时间,提高 GPU 计算单元的有效利用率。
来源: Patentlyze - NVIDIA Multi-Queue AI Data Transfer

跨多计算引擎的编程控制数据多播 (Programmatically Controlled Data Multicasting Across Multiple Compute Engines)

US12020035B2 2022-03-10 申请 | 2024-06-25 授权
核心创新: 单一处理线程为多个其他线程获取数据,通过 L2 缓存仅读取一次数据并形成 "LRC multicast response packet",在网络交叉点处分割 payload 送达所有目标,大幅降低缓存带宽消耗。
技术实现:
  • 主线程发起一次数据获取请求,服务于多个目标处理单元
  • L2 缓存仅读取一次,形成多播响应包
  • payload 在网络交叉点处动态分割,送达所有目标接收者
  • 接收单元发送确认信号回源端
  • 依赖 Cooperative Group Arrays (CGA) 确保线程集群间的同步执行和共享内存可访问性
影响分析: 该专利对分布式训练中的数据并行广播操作至关重要。在多 GPU 的 tensor parallel 场景中,同一权重数据需要分发到多个计算引擎,多播机制可显著减少缓存带宽压力和网络流量。

处理器与内存中的快速数据同步 (Fast Data Synchronization in Processors and Memory)

US20230315655A1 2023-10-05 公开
核心创新: 引入 "store + arrive" 组合指令,将数据写入接收缓冲区的同时更新同步屏障,实现"光速"延迟 (约 0.5 往返时间) 的 GPU 间数据同步,消除传统方案中独立的 flag 更新步骤。
技术实现:
  • 单一的 store-and-arrive 指令同时完成数据写入和同步信号更新
  • 双屏障架构:同步功能分布在消费者侧和生产者侧,消除远程轮询开销
  • 协作组阵列 (CGA) 模型确保并发线程的一致性语义
  • 内存围栏在所有互连路径 (NVLink, PCIe) 上复制,减少额外带宽消耗
  • 支持 Multi-Instance GPU (MIG) 独立执行同步操作
影响分析: 该专利是 NCCL 底层同步原语的硬件级优化,对 AllReduce、AllGather 等集合通信操作有直接影响。在 H100/B200 GPU 集群中可降低集体通信 tail latency 约 20-30%。发明人包括 NVIDIA GPU 架构核心人物 Olivier Giroux 和 Jack Choquette。

AMD 计算通信并行专利

平衡延迟堆叠缓存 (Balanced Latency Stacked Cache)

US20260003794A1 2024-06-28 申请 | 2026-01-01 公开
核心创新: 在 3D V-Cache 基础上进一步探索 L2 缓存堆叠,采用中央放置的缓存控制电路和垂直连接通孔 (connection vias),在多层缓存 die 之间实现平衡的访问延迟,避免传统堆叠方案中远端 die 延迟过高的问题。
技术实现:
  • 中央缓存控制: 缓存控制电路位于堆叠结构的中央位置,最小化到各层缓存 die 的信号路径差异
  • 垂直连接通孔: 在堆叠中心配置垂直通孔作为互联 I/O,连接各层缓存 die
  • 标签先行查找: 在发起垂直访问请求之前先执行标签查找 (tag lookup),减少无效访问
  • 基础 die 集成: 主存储阵列集成在基础 die 上,次级阵列位于上方,由中央逻辑统一管理
  • 平衡延迟设计: 通过中央对称布局确保各层缓存的访问延迟基本一致
影响分析: 该专利是 AMD 3D V-Cache 技术的下一代演进方向。将堆叠从 L3 扩展到 L2,可以进一步大幅提升缓存容量和命中率。平衡延迟设计解决了传统 3D 堆叠中远端 die 访问延迟过高的核心痛点,对 AI 推理和 HPC 工作负载的缓存密集型场景尤为重要。MI500 系列可能采用此技术。

技术实现:

影响分析: 该专利奠定了 AMD CDNA/RDNA 多 chiplet GPU 架构的基础。MI400 系列采用此有源桥接技术实现计算芯粒间的高带宽低延迟通信,直接对标 NVIDIA NVLink 的 chiplet 方案。有源桥接的 LLC 功能减少了跨 die 的内存访问延迟,对大规模矩阵乘法等 HPC 操作尤为关键。

Intel 计算通信并行专利

扩展带宽内存 (eXtended Bandwidth Memory — XBM)

Intel Patent 2025 2025 申请公开
核心创新: 摒弃传统 HBM 的昂贵硅中介层,采用后端金属层薄膜晶体管 (backend-transistor DRAM stacks) 制造 0.5-5GB 容量的 3D 堆叠 DRAM,运行频率 2GHz。通过串行 UCIe 链路 (32 GT/s) 而非传统宽并行接口进行互连,并内置缺陷修复机制。
技术实现:
  • 后端 DRAM 堆叠: 在 BEOL 金属层使用薄膜晶体管制造 DRAM 堆叠,无需传统硅中介层
  • UCIe 互连: 采用 32 GT/s 串行 UCIe 链路替代宽并行接口,降低引脚数和布线复杂度
  • 内置缺陷修复 (BISR): 使用备用通道和冗余阵列克服制造良率问题
  • 基础 die 路由: 内存 I/O 通过基础 die 路由,集成 decode/debug 区域
  • TSV 跨层连接: 垂直硅通孔连接各 DRAM 层
影响分析: XBM 是 Intel 对 HBM 供应链依赖的战略性替代方案。通过消除昂贵的硅中介层并采用标准 BEOL 工艺,XBM 可大幅降低高带宽内存的成本。UCIe 串行互连简化了封装复杂度,但带宽密度可能不及 HBM3e。该方案对 Intel Falcon Shores 和后续 AI 加速器的内存子系统有重要影响。

计算通信并行研究论文

TokenWeave: 分布式 LLM 推理的高效计算-通信重叠

MLSys 2026 Oral Microsoft Research
核心创新: 提出针对分布式 LLM 推理 (而非训练) 的计算-通信重叠方案。通过融合 AllReduce-RMSNorm 内核,利用 NVSHARP/Multimem 硬件特性,仅占用 2-8 个 SM 即可完成通信与归一化的重叠,实现最高 1.28x 延迟加速。
技术细节:
  • 问题识别: 现有方案将计算分解为更小的任务来实现重叠,但在短序列 (推理场景常见) 下性能反而下降
  • 关键洞察: RMSNorm 是 LLM 推理中的关键组件,可以与 AllReduce 融合
  • 融合内核: 新型 fused AllReduce-RMSNorm 内核利用 NVSHARP/Multimem 特性
  • 低资源占用: 仅需 2-8 个流式多处理器 (SM) 即可运行,不影响主计算
  • 有效范围: 在序列长度 >= 1024 时效果显著
  • 性能提升: 最高 1.28x 延迟加速,显著提升整体吞吐量
影响分析: TokenWeave 是首个专门针对 LLM 推理场景的计算-通信重叠方案。与训练不同,推理的序列长度短且延迟敏感,传统分解方案不适用。融合 AllReduce-RMSNorm 的思路巧妙利用了推理过程中必然存在的归一化操作,几乎零额外计算开销地实现通信隐藏。该方案已被 MLSys 2026 接收为 Oral 论文。
来源: arXiv - TokenWeave (2505.11329) | MLSys 2026 Oral | GitHub - microsoft/tokenweave

GPU 加速分布式深度学习中的计算-通信重叠特征分析

IEEE / arXiv 2025 ISCA 2025
核心发现: 首次系统性研究计算-通信重叠对 GPU 性能和能耗的影响。发现重叠执行平均导致 18.9% 的计算减速,但顺序执行仍比重叠慢 10.2%。重叠操作会提高峰值功耗,在严格功率限制下执行时间可增加高达 107%。
关键数据:
  • 计算减速: 重叠执行平均导致 18.9% 的计算性能下降 (资源争用)
  • 净收益: 尽管有减速,顺序执行仍比重叠慢 10.2%,证明重叠整体有效
  • 功耗影响: 重叠操作提高峰值功耗,加剧硬件资源争用
  • 功率限制: 严格功耗限制下,执行时间增加高达 107% (严重降频)
  • 专用核心: 使用专用核心 (如 TMA) 对小模型有益,但加剧大模型的资源争用
影响分析: 该研究揭示了计算-通信重叠的"隐性成本"——并非所有场景都适合激进的重叠策略。对系统设计师而言,需要根据模型规模、硬件配置和功率预算动态调整重叠策略。这为 NVIDIA NeMo 等框架的自适应重叠调度提供了重要的实验依据。
来源: arXiv - Characterizing C-C Overlap (2507.03114) | IEEE Xplore

NCCLX: 面向 100k+ GPU 的集合通信系统

arXiv 2510.20171 Meta, 2025
核心创新: Meta 开发的 NCCLX 集合通信系统,突破 10 万 GPU 规模下的通信瓶颈。针对训练和推理的不同需求优化数据传输,在 Llama4 架构上验证了显著的传输效率提升。
技术细节:
  • 超大规模优化: 专为 100k+ GPU 集群设计,解决传统 NCCL 在超大规模下的扩展瓶颈
  • 训练+推理双模: 同时支持训练的严格同步需求和推理的低延迟需求
  • Llama4 验证: 在 Meta Llama4 架构上验证了传输效率提升
  • 拓扑感知: 感知集群网络拓扑,优化集合通信的路由策略
影响分析: NCCLX 是 Meta 对抗 NVIDIA NCCL 垄断的关键武器。在 10 万 GPU 规模下,传统 NCCL 的树形/环形拓扑效率急剧下降,NCCLX 通过更精细的拓扑感知和分层通信策略解决了这一问题。对国内大模型厂商 (如字节跳动、百度) 的超大规模集群建设有重要参考价值。
来源: arXiv - NCCLX (2510.20171) | arXiv HTML 全文

locality-Aware TLB 加速 GPU 地址翻译 (Accelerating GPU Address Translation Using Locality-Aware TLB)

ACM 2025 ICS 2025 / arXiv 2507.02770
核心创新: 利用 GPU 工作负载的局部性特征优化 TLB (Translation Lookaside Buffer) 设计,减少地址翻译延迟。针对大规模 GPU 动态内存分配场景,提出 warp-aware 的内存重排方案 AlignMalloc,与 UVM 预取对齐。
技术细节:
  • Locality-Aware TLB: 利用 GPU 工作负载的空间/时间局部性优化 TLB 缓存策略
  • AlignMalloc: warp-aware 内存重排,使分配与 UVM 预取行为对齐
  • 大规模动态分配: 针对 GPU 上大规模动态内存分配场景优化
  • DUCATI 后续: 基于 NVIDIA Research 2019 年 DUCATI 工作的进一步演进

趋势展望

多 Chiplet MMU 一致性成为核心挑战

NVIDIA US20260079849A1 专利表明,随着 GPU 进入多 chiplet 时代 (Blackwell/Rubin),跨 die 的 MMU 同步和地址翻译一致性成为必须解决的系统级问题。主从架构是一种务实的选择,但未来可能需要更分布式的方案来避免主 die 成为瓶颈。

参考: US20260079849A1

计算-通信重叠从"always-on"走向"自适应"

ISCA 2025 论文揭示了重叠的隐性成本 (18.9% 计算减速, 107% 功率限制下执行时间增加)。TokenWeave 的融合内核方案代表了更精细的重叠策略——不是简单地并行化,而是找到计算和通信的天然重叠点 (如 RMSNorm)。未来框架需要根据模型规模、功率预算和硬件配置动态调整重叠策略。

参考: TokenWeave | C-C Overlap Characterization

互连开放化趋势加速

三大开放趋势: NVIDIA NVLink Fusion (有限开放 NVLink 端口给第三方)、华为 UB 2.0 开源 (完全开放互连规范)、AMD UALoE (基于以太网标准)。这标志着 GPU 互连从完全封闭走向"有控制的开放",有助于打破单一厂商锁定,但也带来互操作性挑战。

参考: NVLink Fusion | 华为 UB 2.0

内存架构多元化竞争

Intel XBM (后端 DRAM + UCIe) 试图绕过 HBM 的供应链瓶颈和成本问题;AMD 将 3D V-Cache 从 L3 扩展到 L2;NVIDIA 通过 ICMS 实现 KV cache 存储复用;CXL 内存池化提供数据中心级的内存共享。四种路线各有优劣,短期内 HBM 仍将是主流,但中长期多元化趋势明确。

参考: Intel XBM | AMD L2 V-Cache

机密计算与内存安全

NVIDIA WO2026136182A1 专利显示,在多租户 GPU 环境中实现硬件级的内存地址翻译安全正变得日益重要。随着 GPU 云服务的增长,机密计算 (Confidential Computing) 需要从"可选"变为"标配",vMMU 的安全翻译机制将成为 GPU 虚拟化的基础组件。

参考: WO2026136182A1

光电共封装进入实用阶段

NVIDIA Rubin 平台集成 200G SerDes 和光学组件,华为 Atlas 实现 200m+ 光互连。光电共封装 (Co-Packaged Optics) 正在从实验室走向量产,解决了电信号互连在距离和功耗上的物理极限。这对超大规模 GPU 集群 (100k+ GPU) 的部署灵活性至关重要。

参考: NVIDIA Rubin | 华为光互连
