NVLink 模块动态

NVIDIA 官方 2026-09-15

NVLink 6 多层弹性架构: Vera Rubin NVL72 的基础互联

核心要点: NVIDIA 发布 NVLink 6 技术深度解析, 阐述如何为 AI 工厂构建 "原生无损网络"。采用轻量级前向纠错 (FEC) + 物理层重试机制, 基于信用的流量控制防止丢包。引入 "Shadow Engine Recovery" 实现推理工作负载快速恢复, 无需冷重启。该架构是 Vera Rubin NVL72 (72 GPU 单一域) 的基础。
技术细节:
  • 原生无损 Fabric: FEC + PHY Retry 组合实现零丢包传输
  • Shadow Engine Recovery: 推理引擎故障后快速切换, 无需冷重启
  • Vera Rubin NVL72: 72 GPU 单一 NVLink 域, 配合 NVSwitch 托盘
  • 与 NVIDIA Dynamo、NVLink Fusion、NMX Controller 协同工作
  • NVSwitch "Switch Admin State" 使托盘维护变为非中断操作
  • 第三方定制加速器可继承此弹性生态系统
来源: NVIDIA Developer Blog
NVIDIA 官方 2026-08-26

NVLink Fusion: 将 NVHBM 引入下一代 AI 基础设施

核心要点: NVLink Fusion 允许超大规模客户和合作伙伴将定制 XPU 集成到 NVIDIA 机架级系统中。定制硅片可通过 NVLink 6 和 NVLink Switch 嵌入到机架级网络骨干。NVLink-C2C 将定制处理器连接到 Vera CPU。NVHBM 提供约 33% 更高带宽, 回收约 30% 芯片面积。Amazon Annapurna Labs 为首个合作伙伴。
技术细节:
  • NVLink-C2C 连接定制处理器到 CPU (如 Vera CPU)
  • NVHBM: ~33% 更高带宽, ~30% 芯片面积回收, 降低内存功耗
  • 每个定制芯片整体约 30% 性能提升
  • Amazon Annapurna Labs 将 AWS 硅片与 NVIDIA NVHBM 结合
来源: NVIDIA Developer Blog - NVLink Fusion
Bug Issue #1333 | 2026-09-02 (本周更新)

H100 NVL: UVM 拆解死锁导致 NVLink 系统挂起

问题描述: H100 NVL 双 GPU 系统 (通过 NVLink NV12 互联, 26.562 GB/s per link) 上, 开放内核驱动 595.71.05 出现锁序违规 (locking order violation), 导致系统挂起。UVM teardown 断言失败, GPU 分配锁被死线程持有, 冻结所有后续管理命令。物理互联正常, 零 ECC 错误。
关键信息:
  • 硬件: H100 NVL, NVLink NV12 互联
  • 驱动版本: 595.71.05 (open kernel)
  • 警告位置: nv.c:5461 nvidia_dev_put_uuid
  • 根因: UVM teardown 中的锁序违规, 非 NVLink 协议问题
  • 影响: 系统完全挂起, 需要硬重启
来源: GitHub Issue #1333

NVLink C2C 模块动态

NVIDIA 官方 产品页面更新

NVLink-C2C: 芯片间互联技术规格确认

核心要点: NVLink-C2C 将 NVLink 扩展为芯片间互联, 支持定制硅片集成。相比 PCIe Gen 6 PHY, 提供 6 倍能效提升和 3.5 倍面积效率提升。支持 Arm AMBA CHI 和 CXL 行业标准协议。
已确认使用 NVLink-C2C 的系统:
  • Vera Rubin Superchip (2 Rubin GPU + Vera CPU)
  • GB300 NVL72 (72 Blackwell Ultra GPU + 36 Grace CPU)
  • GB200 NVL72
  • DGX Spark
  • Grace CPU Superchip
  • NVLink Fusion (第三方定制硅片)
关键规格:
  • 能效: 比 PCIe Gen 6 PHY 高 6x
  • 面积效率: 比 PCIe Gen 6 PHY 高 3.5x
  • 协议支持: Arm AMBA CHI, CXL
  • Rubin 平台: Vera CPU 通过 NVLink-C2C 连接 2 个 Rubin GPU
来源: NVIDIA NVLink-C2C 产品页 | Rubin 平台新闻稿

趋势展望

短期趋势 (1-4 周)

1. MMU/UVM 稳定性将是核心关注点: 本周 4 个 Critical 级别的 MMU/UVM bug 表明, 随着 Blackwell GPU 和 DGX Spark 的部署扩大, 内存管理子系统的稳定性压力增大。BAR1 VA 耗尽问题 (#1396) 已有社区 PR 修复 (#1403), 预计将在下个版本合入。
2. 615.71.09 回归问题持续发酵: DisplayPort 相关的多个 bug (#1392, #1394, #1405) 和 resume 失败 (#1389) 表明 615 分支需要更多稳定化工作。社区在 NVIDIA 论坛上报告了多起相关案例。
3. 开放内核模块迁移加速: 615.71.09 正式废弃专有内核模块安装, 默认切换到 Coherent Driver-based Memory Management。这将推动更多用户迁移到 nvidia-open, 但也可能暴露更多开放内核模块特有的 bug。

中期趋势 (1-3 月)

1. Vera Rubin 平台准备: NVLink 6 的多层弹性架构和 NVSwitch 托盘热维护特性表明, NVIDIA 正在为 2026 年下半年的 Vera Rubin NVL72 做软件准备。开放内核驱动需要适配新的 NVLink 6 拓扑和 NVSwitch 管理接口。
2. NVLink-C2C 生态扩展: NVLink Fusion 允许第三方定制硅片通过 NVLink-C2C 集成到 NVIDIA 机架系统。Amazon Annapurna Labs 已为首个合作伙伴。预计将有更多定制处理器支持, 开放内核驱动需要适配新的 C2C 拓扑。
3. UVM 子系统重构压力: 多个 UVM 关键 bug (内核 panic、死锁、内存泄漏) 表明 UVM 子系统可能需要更深层的重构, 而非逐个修补。社区贡献者 SammyTourani 近期活跃提交多个 UVM 修复 PR, 显示社区正在积极参与代码改进。

核心洞察

1. MMU/UVM 是本周最活跃且最关键的模块: 4 个 Critical bug 和 4+ 个修复 PR 表明, 随着 Blackwell 和 DGX Spark 部署扩大, 内存管理子系统正面临前所未有的压力。BAR1 VA 耗尽 (#1396) 和 MMU unmap 失败 (#1342) 是用户可感知的最严重问题。
2. 开放内核模块进入关键转型期: 615.71.09 废弃专有内核模块, 默认切换到 Coherent Driver-based MM。这意味着更多用户将使用 nvidia-open, 但也意味着更多 bug 将被暴露。本周的多个 resume 失败和 GPU 脱离总线报告印证了这一趋势。
3. NVLink/NVSwitch/NVLink-C2C 代码层面平静: 本周无新的互联相关 commits 或 PRs。主要动态来自官方技术博客 (NVLink 6 弹性架构) 和产品页面 (NVLink-C2C 规格确认)。这表明互联硬件设计已趋于稳定, 软件适配工作主要在驱动层面。
4. 社区贡献活跃度提升: SammyTourani 本周提交 4+ 个 PR (UVM 编译修复、BAR1 映射、GSP 资源清理、modeset 修复), 显示社区正在积极参与开放内核驱动的代码改进。这种社区参与对驱动长期健康至关重要。
