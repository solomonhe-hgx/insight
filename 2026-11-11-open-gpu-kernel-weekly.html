R620 新分支首发: 620.70.06 正式发布 NEW BRANCH R620

2026-11-05 commit e6a2e01 / Maneet Singh
重大事件: NVIDIA 发布全新 R620 驱动分支，版本号 620.70.06。这是自 R615 以来的首个新分支，标志着 NVIDIA 开源驱动进入新阶段。R620 分支中，专有内核模块正式标记为 deprecated，开源模块成为唯一推荐选项。

NVLink 相关变更:

  • 发布说明确认支持多种 HGX 服务器平台的 NVLink 互联配置
  • Windows 系统仅在 "shared NVSwitch virtualization" 模式下支持 NVLink
  • NVLink 相关代码在 R620 中延续了 R615 的托盘热拔插和分区模式支持
来源: GitHub Release 620.70.06 | NVIDIA Tesla Release Notes | GitHub Commits (e6a2e01)

Issue #1528: RTX 5050 (GB207) Xid 79 — PCIe Completion Timeout 导致总线断开 BUG NEW

2026-11-06 Blackwell Mobile (GB207) / 615.78.08 → 620.70.06 / CachyOS / Kernel 7.3.1
问题描述: Palit RTX 5050 Dual 8GB (GB207) 在轻负载或空闲时随机触发显示故障和桌面冻结。错误序列显示 PCIe Completion Timeout (Non-Fatal)，随后 Xid 79 "GPU has fallen off the bus"，并触发 Xid 154 将 GPU 恢复策略改为 PF FLR。作者在 615.78.08 和 620.70.06 两个版本上均确认问题存在。

错误序列:

  • pcieport 0000:00:01.0: PCIe Bus Error: severity=Uncorrectable (Non-Fatal)
  • [14] PCIe Completion Timeout | Requester | Transaction Layer
  • Xid (PCI:0000:01:00): 79, GPU has fallen off the bus
  • Xid (PCI:0000:01:00): 154, GPU recovery action changed to PF FLR

NVLink 相关性: Xid 79 持续成为 Blackwell 架构在开源驱动中的头号稳定性问题。本周新增 GB207 (RTX 5050) 案例，加上此前的 GB206M (RTX 5070 Mobile #1504)、GB202 (RTX 5090 #1495)、和 AD103 (RTX 5080 #1151)，Xid 79 已覆盖 Blackwell 全系和 Ada 部分型号。

来源: Issue #1528 | 关联 #1504 (RTX 5070 Mobile) | 关联 #1495 (RTX 5090)

Issue #1495: RTX 5090 Xid 79 + 154 — CUDA 推理期间 GPU 总线断开 BUG

2026-10-26 Blackwell (GB202) / CUDA Inference Workload
问题描述: RTX 5090 在运行 CUDA 推理工作负载时触发 Xid 79 和 Xid 154 错误组合。这与 #1528 的错误模式完全一致，表明 Blackwell 架构在高负载推理场景下的 PCIe/NVLink 物理层存在系统性稳定性问题。该 Issue 在本周持续活跃。
来源: Issue #1495

NVLink C2C 模块更新

R620 默认启用 CDMM — 与 C2C 统一内存架构方向一致

R620 延续 CDMM 作为默认内存管理模式 R620

2026-11-05 Coherent Driver-Based Memory Management / C2C 统一内存
架构变更: R620 分支延续并强化了 R615 引入的 CDMM (Coherent Driver-Based Memory Management) 作为一致性平台默认模式。CDMM 减少 NUMA 节点暴露，与 NVLink-C2C 统一内存架构方向完全一致。在 R620 中，NUMA 模式仍完全支持，但需通过内核模块参数显式配置。
来源: Tesla Release Notes 620.70.06

Vera Rubin 平台 NVLink-C2C: 1.8 TB/s 一致性互联 ROADMAP

1.8 TB/s coherent / 统一地址空间 / Vera CPU + Rubin GPU
核心规格: NVLink-C2C 在 Vera Rubin 平台提供 1.8 TB/s 一致性带宽，连接 Vera CPU (88 Olympus 核心, 1.5TB LPDDR5X) 与 Rubin GPU (224 SMs, 288GB HBM4)。CPU 与 GPU 共享统一地址空间，对操作系统和上层软件透明。CDMM 的默认启用为 C2C 统一内存的软件栈铺平了道路。
来源: NVIDIA Blog: Vera Rubin Platform | NVLink-C2C 官方页面

MMU/UVM 模块更新

本周 4 个 MMU 关键 PR + R620 vmalloc 路径 + NUMA 修复

R620: >2 GiB 内存分配改用 vmalloc() 路径 R620 MMU

2026-11-05 620.70.06 / 大块内存分配 / 碎片化缓解
关键变更: R620 分支中，超过 2 GiB 的内存分配现在使用替代的 vmalloc() 路径。这直接解决了上周 Issue #1516 报告的 order-3 kzalloc 碎片化问题——即使系统有空闲内存，物理连续分配失败也会触发 OOM killer。vmalloc 回退允许虚拟地址空间分配，大幅降低碎片化场景下的分配失败率。
来源: Tesla Release Notes 620.70.06

R620: 修复 NUMA 无内存节点内核崩溃 R620 FIX

2026-11-05 NUMA / open GPU modules / kernel panic
修复内容: 修复了在 NUMA 系统上部分节点无内存时，使用开源 GPU 内核模块触发 kernel panic 的问题。这对多路服务器和工作站平台至关重要，此前这些配置在 R615 分支上会导致系统崩溃。
来源: GamingOnLinux: 620.70.06

R620: Tensor Map 编码 MMU Fault 变通方案 R620

2026-11-05 MMU fault / tensor map / bit clear workaround
变通方案: R620 发布说明中记录了一个 MMU fault 的变通方案: 在编码 tensor map 时清除特定位以防止 MMU 故障。这表明在 R615 分支中存在一个未记录的 MMU 页表处理边缘情况，R620 通过软件层面的位操作规避了硬件级故障。
来源: Tesla Release Notes 620.70.06

PR #1532: VA 映射修复移植到 620.70.06 — partial unmap 粒度与失败路径 PR MMU

2026-11-09 VA mapping / partial unmap / 4GB GPU / Vulkan
核心修复: 将此前针对 615 分支的 VA 映射修复移植到新的 R620 分支。问题源于内存管理在三个精度层级跟踪分配: 硬件页表条目 (PTE)、客户端列表 (精确字节范围)、和虚拟地址空间。Partial unmap 可能释放整页但留下客户端列表碎片，导致后续释放操作崩溃。

修改文件:

  • virt_mem_allocator_gm107.c — 防止释放例程在错误时擦除活跃映射
  • virtual_mem.c — 对齐 partial unmap 到页大小，忽略未注册范围的 unmap 请求
  • rs_server.c — 确保服务端表对齐 unmap 到正确页边界

影响场景: 主要影响 4GB 笔记本 GPU (如 RTX 3050 Laptop) 在高内存压力 Vulkan 应用中的稳定性。错误表现为 NVRM: refAddInterMapping: Duplicate inter mapping detected 和 Assertion failed: pDmaMappingInfo != NULL。

来源: PR #1532 | 关联 PR #1483 (615 版本)

PR #1525: DRM 原子状态分配允许 vmalloc 回退 — 解决 OOM Killer 误触发 PR MEMORY

2026-11-05 nvidia-drm-modeset.c / kvzalloc / OOM killer
核心修复: 将 kernel-open/nvidia-drm/nvidia-drm-modeset.c 中的原子状态分配从 kzalloc() 改为 kvzalloc(..., GFP_KERNEL)，配合 kvfree() 释放。这允许在物理连续内存碎片化时回退到虚拟内存分配，直接解决 Issue #1516 报告的 OOM killer 问题。

社区验证: 一位用户报告了 37 次 OOM-killer 事件，均因无法分配 32 KiB 物理连续块触发。确认此补丁完全消除了问题。多个 Linux 发行版已被请求在其自定义内核构建中携带此 PR。

来源: PR #1525 | 关联 Issue #1516

PR #1530: 修复 dmem_cgroup_register_region() 调用 — 设备内存 cgroup 安全 PR

2026-11-07 device memory cgroup / format string safety
修复内容: 将 dmem_cgroup_register_region() 中的 name 参数从直接作为格式字符串改为通过 %s 参数传递。这是一个安全性修复，防止格式字符串注入风险，与 Linux 内核安全编码规范对齐。
来源: PR #1530

趋势展望

短期趋势 (1-4 周)

R620 分支将快速成为主流

620.70.06 作为 R620 首发版本，Arch Linux 和 Ubuntu 预计将在 1-2 周内通过官方仓库推送。由于 Blackwell 架构强制要求开源内核模块，所有 RTX 50 系列用户将自动迁移到 R620。社区反馈中的 VA-space 映射和 RAM 占用问题可能催生更多补丁 PR。

PR #1525 (vmalloc 回退) 和 #1532 (VA 映射修复) 预计即将合并

两个 PR 都解决了高优先级内存管理问题，且 #1525 已有社区验证数据 (37 次 OOM 事件消除)。R620 的发布增加了合并紧迫性——新分支需要这些稳定性修复。预计将同步移植到 R615 和 R620 两个活跃分支。

Xid 79 需要 NVIDIA 在 R620 中紧急修复

#1528 作者已在 620.70.06 上确认问题未修复。Xid 79 现在覆盖了 Blackwell 全系 (GB202/GB203/GB206/GB207) 和部分 Ada 型号。作为新分支的首发版本，R620 未能解决这个最广泛的稳定性问题，可能影响社区对开源驱动的信心。

中期趋势 (1-3 月)

R620 内存管理子系统全面升级

R620 引入了 >2 GiB vmalloc 路径、NUMA 修复、CDMM 默认模式等多项内存管理变更。这些变更的方向是减少物理连续内存依赖、降低碎片化影响、统一 NUMA/CDMM 内存模型。预计后续 R620.x 版本将继续深化这一方向，可能引入更多 vmalloc 回退和页表优化。

Vera Rubin 平台驱动准备加速

R620 分支的发布为 Vera Rubin 平台的驱动支持铺平了道路。代码库已包含 rubin 架构的 MMU 目录。CDMM 默认模式与 NVLink-C2C 统一内存架构方向一致。预计 R620.x 后续版本将增加 NVLink 6 和 C2C 1.8 TB/s 的完整开源驱动支持。

专有模块废弃加速社区转型

R620 正式标记专有模块为 deprecated，Blackwell 强制使用开源内核模块。这将推动整个 Linux 图形栈 (Wayland 合成器、显示管理器、桌面环境) 加速适配开源驱动特性。社区 PR 的质量和数量将成为生态健康的关键指标——本周 #1525 和 #1532 都是高质量的外部贡献。

核心洞察

1. R620 新分支发布 — NVIDIA 开源驱动进入新纪元

620.70.06 标志着全新 R620 分支的开始。关键变更包括: >2 GiB 内存分配改用 vmalloc() 路径、NUMA 无内存节点 kernel panic 修复、CDMM 延续为默认模式、Wayland 显式同步性能提升、以及专有内核模块正式标记为 deprecated。这是自 R615 以来的首个新分支，1,264 个文件变更表明这是一次大规模重构而非增量更新。

2. 内存管理成为 R620 核心改进方向 — vmalloc + VA 映射 + cgroup

本周 7 个新 PR 中有 4 个直接涉及内存管理: PR #1532 (VA 映射 partial unmap 修复移植到 R620)、#1525 (vmalloc 回退解决 OOM killer)、#1530 (dmem cgroup 安全)、加上 R620 自身的 >2 GiB vmalloc 路径变更。这些变更共同指向一个方向: 减少对物理连续内存的依赖，增强碎片化场景下的鲁棒性，与 CDMM 统一内存管理架构对齐。

3. Xid 79 在 Blackwell 全系扩散 — R620 未能解决

本周新增 #1528 (RTX 5050 GB207) 确认 Xid 79 已覆盖 Blackwell 全系: GB202 (RTX 5090)、GB203 (RTX PRO 4000)、GB206M (RTX 5070 Mobile)、GB207 (RTX 5050)。错误模式一致: PCIe Completion Timeout → Xid 79 "fallen off the bus" → Xid 154 recovery。作者在 620.70.06 上确认问题未修复，这对新分支的可靠性形象构成挑战。

4. 专有模块 deprecated + Blackwell 强制开源 — 社区转型不可逆

R620 正式标记专有内核模块为 deprecated，而 Blackwell 架构 (RTX 50 系列) 强制要求使用开源内核模块。这意味着数百万 Blackwell 用户将成为开源驱动的 "第一梯队" 测试者，没有专有驱动回退选项。社区反馈中的痛点 (VA-space 映射、RAM 占用、EDID 故障、DLSS 问题) 将直接推动开源驱动的加速迭代。外部贡献者的 PR 质量和数量 (#1525 vmalloc, #1532 VA mapping, #1500 BAR1) 表明社区参与正在深化。
