统一内存 GPU 的局部化模式 (Localized Mode for Unified Memory GPU)

DE102024121954A1 申请: 2024-08-01 | 公开: 2025-03-06 Memory MMU
核心创新: GPU 可"选择性地限制执行仅使用本地连接的存储组件"以降低延迟,同时在需要额外容量时允许远程访问。通过在页表中引入局部化属性位,实现按 64MB 块级别的内存局部化映射。
技术实现:
  • 设备划分为微单元 (micro-GPU),每个微单元包含处理核心、交叉开关和专用 DRAM,单元间通过 NoC 或 die 间链路通信
  • MMU 内的 AMAP 模块可在交错步幅映射 (interleaved stride mapping) 和集群绑定映射 (cluster-bound mapping) 之间切换
  • 一个属性位决定局部化和非局部化内存访问,转换硬件读取页表条目内的局部化标志
  • 启用后对齐块 (64MB 段) 专门映射到特定微单元的 DRAM,调度器将线程束路由到与其数据共享相同物理集群的核心
  • 每个对齐段独立切换模式,支持混合工作负载策略;结合 Cooperative Group Array (CGA) 实现执行绑定
影响分析: 直接支持 NVIDIA Blackwell 及后续 GPU 架构中的多 chiplet 设计。在 GB200 NVL72 等大规模系统中,减少跨 die 通信延迟对训练和推理性能至关重要。局部化内存模式可减少 30-50% 的跨集群流量,显著提升能效。对于 LLM 推理场景,KV cache 的局部化分配可降低 tail latency。
来源: Google Patents - DE102024121954A1

LLM 动态 KV Cache 调度 (Dynamic KV Cache Scheduling for LLMs)

US20260133908A1 申请: 2025-02-13 | 公开: 2026-05-14 Memory Cache
核心创新: 为 Transformer 注意力机制创建分层 KV Cache 存储结构。频繁使用的 KV 对保留在高速片上存储,不关键信息移至较慢二级位置。调度器评估检索概率,按需取回卸载数据 ("just-in-time"),类似操作系统的按需分页机制。
技术实现:
  • 分层存储架构:热数据 (hot KV pairs) 驻留在 HBM 或 SRAM 中,冷数据迁移至 SSD 或远程内存
  • 调度器基于注意力分数评估每个 KV 对的检索概率,预测哪些数据即将被使用
  • 按需分页 (demand-paging) 机制:在数据实际需要之前,提前将其从二级存储取回到快速存储
  • 支持扩展上下文长度,使模型能够处理远超物理内存容量的序列
  • 与操作系统虚拟内存管理类似,实现 KV Cache 的"换入/换出"策略
影响分析: 解决 LLM 推理中最大的内存瓶颈之一。当前 LLM 服务系统 (如 vLLM, TensorRT-LLM) 受限于 KV Cache 占用的 GPU 内存。该专利允许有效无限上下文长度,同时保持低延迟。对长文档理解、代码生成和多轮对话场景有重大影响。
来源: Patentlyze - US20260133908A1

缓存感知 GPU 内存处理 (Cache-Aware GPU Memory Processing)

US20260203220A1 申请: 2025-01-16 | 公开: 2026-07-16 Cache Memory
核心创新: 处理器主动决定如何从片上高速存储中拉取数据块,通过评估多个计算线程对数据的使用方式,最小化重复取取,节省能耗。支持多达五种动态切换的访问模式。
技术实现:
  • 自适应交换 (Adaptive Swizzling): 重新排列存储中的数据布局以减少访问冲突并提高复用率
  • 连续光栅化 (Continuous Rasterization): 按与传统图形像素处理一致的扫描序列取数据
  • 交替 k 阶遍历 (Alternating k-order): 切换遍历方向以在连续操作期间保持活跃的缓存内容
  • 周期性 CTA 同步 (Periodic CTA Synchronization): 在特定间隔对齐计算线程阵列以协同使用共享存储
  • 显式块驱逐 (Explicit Tile Eviction): 主动清除特定未使用的数据块以为后续需求腾出空间
  • 基础数据通过"交换模型 (swizzle model)"组织,将数据映射到物理地址以防止访问瓶颈
影响分析: 该专利对 GPU 的 L1/共享内存层级有深远影响。五种可切换的缓存访问模式使 GPU 能够针对不同工作负载 (图形、计算、AI) 优化数据流。对 Blackwell 架构中的结构化稀疏计算和 AI 推理的 tile-based 处理特别重要。可减少 20-40% 的缓存未命中率。
来源: Patentlyze - US20260203220A1

AI 模型智能 KV Cache 内存管理 (Smarter KV Cache Memory for AI Models)

US20260220041A1 申请: 2025-01-30 | 公开: 2026-07-30 Memory Cache
核心创新: 采用"两阶段过滤系统,只保留重要的音符"来减少硬件需求。第一阶段通过动态池化技术粗粒度淘汰"不太可能再次有用"的数据;第二阶段使用混合注意力机制进行细粒度处理,聚类剩余记录并执行"稀疏注意力"。
技术实现:
  • 第一阶段 - 粗粒度淘汰: 通过动态池化技术识别并移除低价值 KV 对,减少缓存占用
  • 第二阶段 - 细粒度处理: 混合注意力机制对剩余 KV 对进行聚类,记录极值,执行稀疏注意力以隔离最高优先级的词片段
  • 完全"无需训练 (training-free)"的方法, operators 可以在运行模型时立即部署,无需重建神经架构
  • 与 PagedAttention 等现有 KV Cache 管理方案互补,提供更智能的驱逐策略
影响分析: 与 US20260133908A1 (动态 KV Cache 调度) 形成互补。该专利关注"哪些 KV 对应该被保留",而前者关注"KV 对放在哪里"。两者结合可实现完整的智能 KV Cache 管理系统。无需训练的特性使其可快速集成到现有推理框架中。
来源: Patentlyze - US20260220041A1

封装内与封装外组合内存系统 (Combined On-Package and Off-Package Memory System)

US20230393788A1 申请: 2023-08-23 | 公开: 2023-12-07 Memory
核心创新: 定制逻辑基座将内部高速存储堆栈和外部大容量模块聚合为单一可寻址空间。系统划分为"近内存池 (near memory pool)"追求速度,"远内存池 (far memory pool)"追求容量,并通过透明迁移引擎自动在两者间移动数据。
技术实现:
  • 统一架构:定制硅层桥接处理器与内部 HBM 堆栈和外部 CXL/DDR 模块
  • 智能路由:制造电路引导流量以维持不同计算工作负载的性能标准
  • 透明迁移引擎:自动在"近"和"远"内存池之间移动数据,绕过主芯片以节省功耗和带宽
  • 交错访问:控制器交替向内部和外部模块发送请求以最大化总吞吐量
  • 支持 Fabric-Attached Memory 架构,实现内存资源的池化和共享
影响分析: 该专利是 NVIDIA 应对 AI 模型参数量爆炸式增长的关键基础设施技术。通过在封装内外构建分层内存,可在不显著增加延迟的情况下扩展可用内存容量。对万亿参数模型的训练至关重要,因为单节点 HBM 容量往往不足。
来源: Google Patents - US20230393788A1

多播与反射内存行为实现内存模型一致性 (Multicast and Reflective Memory Behavior for Memory Model Consistency)

US12326820B2 申请: 2022-01-18 | 授权: 2025-06-10 Communication Interconnect
核心创新: 单一内存访问请求可被传播到多个物理地址,跨多个处理单元同时完成数据事务。引入"反射内存"概念:节点请求自身本地数据时,仍将包发送到外部交换机,再由交换机"反射回"设备,确保统一路径和可预测延迟。
技术实现:
  • 互连路由: 中心交换机作为"一致性互联结构"连接设备,翻译并路由内存包跨网络
  • 反射内存行为: 消除不可预测延迟和竞态条件,本地数据请求通过统一路径确保一致性延迟
  • 地址翻译: 虚拟地址决定路由行为,多播指针同时映射到多个物理位置,标准指针定位单一物理位置
  • 一致性约束: 系统强制执行严格规则,确保"使用多播处理请求与单播执行一致",维护内存完整性
  • 优化工作负载: 通过同时广播数据加速集体操作如 AllReduce,大幅减少深度学习中的带宽开销
  • 可选择对应用程序隐藏多播机制或通过"独立的多播和单播指令"暴露
影响分析: 该专利是 NVSwitch 多播能力的硬件基础。反射内存概念确保了在多 GPU 系统中,无论数据位于本地还是远程,延迟都是确定性的。这对 NCCL 的 AllReduce、AllGather、ReduceScatter 等集合通信操作至关重要。在 GB200 NVL72 等 72-GPU 系统中,多播可将集合通信效率提升 2-3 倍。
来源: Google Patents - US12326820B2

消除 AI 芯片间共享数据等待 (Stop AI Chips From Waiting on Shared Data)

US20260170317A1 申请: 2024-12-18 | 公开: 2026-06-18 Communication Memory
核心创新: 解决跨数百个芯片训练大型 AI 模型时的通信瓶颈。系统评估"激活值 (activations)"——神经网络层间产生的中间值。当不同处理器需要相同激活值时,架构主动将相关信息预先复制到两个单元,消除等待时间。
技术实现:
  • 专用处理器电路管理数据集在多个加速器间的划分方式
  • 有意复制重叠信息 (overlap duplication),而非严格隔离分区
  • 激活值驱动的复制策略:基于中间计算结果判断哪些数据需要被共享
  • 复制量与重叠程度成正比,防止在很少共享数据的芯片上浪费内存
  • 同时适用于训练 (training) 和推理 (inference) 场景
  • 减少处理器空闲等待时间,加速整体训练运行
影响分析: 该专利直接针对大规模分布式训练中的"通信墙"问题。在万亿参数模型训练中,激活值的重计算或传输是主要瓶颈之一。通过预复制重叠激活值,可减少 30-50% 的跨节点通信量。与 NCCL 的通信原语互补,在系统层面优化训练效率。
来源: Patentlyze - US20260170317A1

处理器与内存中的快速数据同步 (Fast Data Synchronization in Processors and Memory)

US20230315655A1 申请: 2022 | 公开: 2023-10-05 Communication Interconnect
核心创新: 引入 "store + arrive" 组合指令,将数据写入接收缓冲区的同时更新同步屏障,实现"光速"延迟 (约 0.5 往返时间) 的 GPU 间数据同步。双屏障架构消除远程轮询开销。
技术实现:
  • 单一的 store-and-arrive 指令同时完成数据写入和同步信号更新,消除传统方案中独立的 flag 更新步骤
  • 双屏障架构:同步功能分布在两个屏障上——一个位于消费者侧,一个位于生产者侧,消除远程轮询开销
  • 协作组阵列 (CGA) 模型:确保并发线程执行的一致性语义,内存围栏"在所有互连路径上复制"
  • Multi-Instance GPU (MIG) 支持:允许多个 GPU 实例独立执行同步操作
  • 内存围栏在所有路径 (包括 NVLink, PCIe) 上复制,减少额外带宽消耗
影响分析: 该专利是 NCCL 底层同步原语的硬件级优化,对 AllReduce、AllGather 等集合通信操作有直接影响。在 H100/B200 GPU 集群中,可降低集体通信的 tail latency 约 20-30%。发明人团队包括 NVIDIA GPU 架构核心人物 Olivier Giroux 和 Jack Choquette。

MMU / 地址转换 / 虚拟化

虚拟化环境中的内存访问安全 (Securing Memory Accesses in a Virtualized Environment)

US20200356492A1 申请: 2020-07-23 | 公开: 2020-11-12 MMU Memory
核心创新: 建立全局寻址方案,目标节点"将本地虚拟地址范围导出到 FLA 空间"。多阶段翻译管线:请求处理器将本地虚拟地址转换为全局 Fabric 地址,到达后接收节点将其翻译为"客户物理地址 (GPA)",再次本地翻译解析为实际"系统物理地址 (SPA)"。
技术实现:
  • 统一寻址框架: 全局寻址方案中不同处理器共享公共寻址视图,尽管拥有独立物理硬件
  • 多阶段翻译管线: VA -> FLA (Fabric Logical Address) -> GPA (Guest Physical Address) -> SPA (System Physical Address)
  • 凭证验证: 内存请求携带"关联标识符 (affiliation identifier)",表示安全上下文或权限层级,目标节点在响应前评估
  • TLB 优化: 请求节点可使用超大 TLB 页面,允许映射巨大的连续全局地址块,与目标硬件管理的碎片化物理内存分配完全解耦
  • 隔离保障: "不同应用程序可以相互隔离",同时仍利用共享集群资源
影响分析: 该专利是 NVIDIA MIG (Multi-Instance GPU) 和 GPU 虚拟化的安全基础。多阶段地址翻译机制支撑了 NVIDIA GPU 在云环境中的安全共享。超大 TLB 页面设计对减少地址翻译开销至关重要,特别是在大规模 AI 训练集群中。该架构也是 NVIDIA Fabric Manager 和 Magnum IO 的底层技术基础。
来源: Google Patents - US20200356492A1

分布式共享内存 (Distributed Shared Memory - DSMEM)

US20230289189A1 申请: 2022-03-10 | 公开: 2023-09-14 Communication Memory Interconnect
核心创新: DSMEM 由分布在多个流式多处理器 (SM) 上的内存块组成,允许一个 SM 上的线程访问属于另一个 SM 的内存分配,前提是它们属于同一"协作组阵列 (CGA)"。支持跨 SM 的直接读写和原子操作,无需通过全局内存或 L2 缓存。
技术实现:
  • 跨 SM 可访问性: DSMEM 允许一个 SM 直接写入另一个 SM 的本地内存,大幅降低延迟
  • 硬件并发保证: 系统确保特定 CGA 内的所有 CTA 同时启动,co-residency 保证实现安全的低延迟数据共享
  • 内存映射: DSMEM 集成到通用内存地址空间,专用内存窗口映射本地 DSMEM 段,使用逻辑 CTA 标识符索引
  • 路由机制: 每个 SM 维护特定映射表,将逻辑 CTA 标识符转换为物理 SM 目标
  • 性能优势: 减少 Split-K 并行归约等深度学习工作负载对全局内存的依赖
影响分析: DSMEM 是 NVIDIA GPU 片上通信架构的重大演进。传统上,GPU SM 之间只能通过全局内存 (经过 L2) 通信,延迟高。DSMEM 使 SM 间通信延迟降低一个数量级,对 Transformer 注意力计算、Split-K 归约等需要频繁跨 SM 数据交换的操作至关重要。该架构是 Blackwell 架构高效支持 LLM 推理的关键硬件特性之一。

趋势展望

趋势 1: AI 驱动的内存管理

NVIDIA 正在将 AI 技术应用于内存管理本身。从 KV Cache 的智能调度 (US20260133908A1) 到智能淘汰 (US20260220041A1),再到互连速度的 AI 预测调节 (US20260194956A1),AI 正在成为系统资源管理的核心决策引擎。这预示着未来 GPU 将具备"自我优化"能力。

趋势 2: 多层级内存层次结构

从片上 DSMEM (US20230289189A1) 到封装内 HBM (US20230393788A1),再到 die 间局部化 (DE102024121954A1),NVIDIA 正在构建越来越精细的内存层次结构。每一层都有专门的优化策略,从 SM 级到 chiplet 级到节点级,形成完整的内存拓扑。

趋势 3: 通信与计算的深度融合

多播/反射内存 (US12326820B2) 和 store+arrive 同步 (US20230315655A1) 表明 NVIDIA 正在模糊计算和通信的边界。未来的 GPU 互连将不再区分"本地"和"远程"操作,而是提供统一的内存语义,使分布式训练像单芯片编程一样简单。

趋势 4: 数据中心级优化

VM 拓扑感知放置 (US20260195187A1) 和互连功耗优化 (US20260194956A1) 显示 NVIDIA 的视野已从单芯片扩展到整个数据中心。未来的 NVIDIA 不仅优化 GPU 架构,还优化 GPU 在数据中心中的部署方式,实现从硅到系统的全栈优化。

关注要点

KV Cache 管理将成为 LLM 推理的核心竞争力: 两篇 KV Cache 专利 (US20260133908A1 + US20260220041A1) 的组合将显著提升 NVIDIA GPU 在 LLM 推理场景的内存效率,可能拉开与 AMD MI300X 的差距。

Multi-chiplet GPU 的内存局部化至关重要: DE102024121954A1 直接支持 Blackwell 及后续架构的多 chiplet 设计。随着 GPU die 数量增加,跨 die 通信延迟管理将成为性能瓶颈。

NCCL 的硬件级优化持续深化: 多播 (US12326820B2)、快速同步 (US20230315655A1) 和激活值预复制 (US20260170317A1) 从不同层面优化集合通信,NCCL 的性能将持续受益于硬件创新。

建议关注 NVIDIA 后续专利公开: 2025 年提交的大量专利 (特别是互连和内存管理领域) 将在 2026 年下半年至 2027 年陆续公开,可能揭示 Rubin 架构的更多技术细节。
