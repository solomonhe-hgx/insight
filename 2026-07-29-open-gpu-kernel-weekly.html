NVIDIA 官方博客: NVLink 6 详解

NVLink 6 2026-07-20

NVIDIA NVLink: The Scale-Up Network for AI Factories

带宽与拓扑：第六代 NVLink 每 GPU 提供 3.6 TB/s 带宽，机架级 GPU 带宽达 260 TB/s，采用 all-to-all 拓扑确保加速器间均匀通信。

GPU 支持：当前支持 Vera Rubin NVL72 机架中的 72-GPU 域，使用 NVLink 6 switch chips（每 tray 4 颗），通过 5,000 根线缆互连。未来路线图目标支持最多 1152 GPUs。

网内计算：引入 130 TFLOPS 网内计算加速集合操作。弹性升级包括热插拔 switch trays 和动态流量重路由。

对比优势：相比标准以太网，延迟降低 3x，包速率提升 10x。相比 Hopper 代，Blackwell 架构实现 50x tokens/watt 提升。

610.43.03 MMU/UVM 重大变更

UVM API v14 API 版本升级

UVM API Revision 14: 移除 Range Groups，重命名 HMM→CDMM

移除的 API：

  • UVM_CREATE_RANGE_GROUP / UVM_DESTROY_RANGE_GROUP
  • UVM_SET_RANGE_GROUP
  • UVM_PREVENT_MIGRATION_RANGE_GROUPS / UVM_ALLOW_MIGRATION_RANGE_GROUPS

重命名：

  • UVM_API_RANGE_TYPE_HMM → UVM_API_RANGE_TYPE_CDMM
  • UVM_API_RANGE_TYPE_ATS → UVM_API_RANGE_TYPE_NUMA

含义：Range Groups 机制被完全移除，UVM 内存管理转向更细粒度的 VA range 管理。HMM 重命名为 CDMM (Coherent Device Managed Memory)，反映 NVIDIA 对一致性设备内存管理的新定位。

文件: kernel-open/nvidia-uvm/uvm.h, kernel-open/nvidia-uvm/uvm.c, kernel-open/nvidia-uvm/uvm_api.h

技术趋势分析

Rubin 架构开源驱动就绪

610.43.03 新增 Rubin (GR100) UVM 模块，包括 MMU、fault buffer、架构初始化代码。表明 NVIDIA 在 Rubin 硬件发布前就已开始开源驱动适配。

重大进展

UVM 内存管理范式转变

Range Groups 机制被完全移除，HMM 重命名为 CDMM，ATS 重命名为 NUMA。UVM 正从传统的 managed memory 模型转向更清晰的 NUMA 统一内存模型。

架构演进

NVLink 进入机架级时代

NVLink 6 实现 3.6 TB/s/GPU、260 TB/rack，支持 1152 GPU 域。网内计算 (130 TFLOPS) 和热插拔 switch 使 AI 工厂架构成为现实。

快速演进

短期趋势 (1-3 个月)

Rubin UVM 完善

当前 Rubin 文件已添加但多为空壳 (0 行变更)。预计后续 release 将填充实际实现代码，包括 MMU 页表操作、fault handling、copy engine 等。

CDMM 功能落地

HMM→CDMM 重命名伴随 cdmm_enabled 标志和断言。预计 CDMM pageable migration 路径将在后续版本中完善。

Blackwell 稳定性修复

社区反馈的 Xid 79、P2P 数据损坏、性能限制器等问题预计将在 610.x 后续 hotfix 中解决。

中期趋势 (3-12 个月)

NVLink-C2C 生态扩展

1.8 TB/s 一致性带宽 + 7x PCIe Gen6 优势，将推动更多 CPU-GPU 异构计算平台采用 NVLink-C2C。开源驱动需要完善 C2C 链路管理支持。

1152 GPU 域支持

NVLink 6 路线图目标 1152 GPUs。开源驱动需要扩展 UVM 拓扑发现、peer access 管理、fault isolation 等能力以支持超大规模 GPU 集群。

网内计算开源适配

NVLink 6 的 130 TFLOPS 网内计算需要在开源驱动中暴露相应 API，用于加速集合通信操作 (AllReduce, AllGather 等)。

核心洞察

开源驱动与硬件同步

Rubin 架构在硬件发布前就已进入开源驱动，表明 NVIDIA 正将开源驱动作为一等公民对待。这对 Linux 数据中心生态意义重大。

UVM 简化与现代化

移除 Range Groups、重命名 HMM→CDMM，UVM 正在经历架构简化。这降低了代码复杂度，也为新的内存管理特性铺平道路。

Blackwell 成熟度挑战

尽管 Blackwell 驱动已发布数月，但 Xid 79、P2P 数据损坏等严重问题仍未解决。开源社区需要更多稳定性投入。

NVLink 驱动缺口

开源驱动中 NVLink/NVSwitch 相关代码变更较少，大部分 NVLink 管理仍依赖闭源 RM。未来需要更多 NVLink 拓扑发现和配置的开源实现。
