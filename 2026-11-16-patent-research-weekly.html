NVIDIA 通信 / MMU / Memory 专利

动态KV缓存调度器 (Dynamic KV Cache Scheduler for LLMs)

US20260133908A1 2026-05-14 公开
核心创新: 提出分层KV缓存内存管理系统,根据token的实时效用动态分配缓存注意力数据,防止硬件瓶颈。采用类似操作系统"按需调页"模型的连续调度算法,在受限硬件上实现扩展对话范围。
技术实现:
  • 分层KV缓存:多级存储层次包括处理器内部高速内存、片外二级存储和删除类别
  • 效用评估算法:连续调度算法实时评估token相关性,类似OS按需调页模型
  • 动态分配:根据当前效用动态分配缓存资源,防止硬件瓶颈
  • 扩展对话:在受限硬件上支持更长的对话上下文
  • 精确检索:在需要时精确检索关键信息,优化内存使用效率
影响分析: 该专利直接解决LLM长上下文推理中的KV cache内存瓶颈。在128K+ token序列场景中,单个GPU的HBM往往不足以容纳完整KV cache。通过分层动态调度,可扩展有效内存容量,降低推理延迟。对NVIDIA NVL72等多GPU系统的推理性能有直接优化作用。
来源: Patentlyze - NVIDIA Dynamic KV Cache Scheduling

多芯片GPU本地内存路由 (Multi-Chip GPU Local Memory Routing)

US20260288335A1 2026-09-24 公开
核心创新: 针对多chiplet GPU架构,通过将图形管线属性本地化写入各芯片的本地存储("一致性点"内存),大幅减少跨die通信开销。采用"粗粒度交替虚拟内存"布局,大块交替分配给各芯片,而非字节级交织。每个die独立渲染特定显示区域,仅在必要时通过die间互连交换数据。
技术实现:
  • 多芯片架构:每个处理die负责特定屏幕区域的渲染,独立运行
  • 本地化存储:管线参数和簿记结构保留在物理连接的本地存储中
  • 一致性点:各芯片维护本地"point of coherence"权威性存储
  • 粗粒度交替:大块交替虚拟内存布局,非字节级交织
  • 最小化跨die通信:仅在必要时通过高速互连交换关键数据
影响分析: 该专利直接支持NVIDIA Blackwell及后续GPU架构中的多chiplet设计。在GB200 NVL72等大规模系统中,减少跨die通信等待时间对训练和推理性能至关重要。本地化存储策略可减少30-50%的跨集群流量,显著提升能效。对LLM推理场景中的tail latency优化尤为关键。
来源: Patentlyze - NVIDIA Multi-Chip GPU Local Memory Routing

内存管理增强技术 (Enhanced Memory Management for GPU)

US20260349929A1 2026 公开
核心创新: 通过警报机制和内存重组增强并发处理和数据传输效率。当处理单元完成特定数据块计算后,发送警报触发该块的数据传输,同时继续计算剩余数据块,防止处理中断。在发送前重组内存地址以适配标准库调用,传输完成后恢复原始序列。
技术实现:
  • 警报机制:处理单元完成数据块后立即触发传输,无需等待全部完成
  • 并发执行:数据传输与计算并行进行,防止处理中断
  • 内存重组:发送前重新排列内存地址以适配标准库调用
  • 序列恢复:传输完成后恢复原始内存序列
  • 时序调整:最大化并发执行效率的调度优化
影响分析: 该专利对NVIDIA GPU的内存管理系统进行了重要增强。通过警报驱动的并发传输机制,可显著提升大规模AI训练中的梯度同步效率。内存重组技术使标准DMA库无需修改即可适配新型传输模式,降低了软件栈升级成本。
来源: Justia Patents - US20260349929

NCCL CFT Device API - 计算Fabric传输设备接口

NCCL v2.31+ / 技术文档 2026 更新
核心创新: NCCL v2.31引入Compute Fabric Transport(CFT)设备级API,允许自定义kernel直接执行fabric操作(put/get/reduce/barrier)。采用对称内存分配、16字节对齐规则、计数任务消除传统fence-flag同步模式。支持跨代理fence确保不同代理类型(如Fabric和Generic)间的内存可见性。
技术实现:
  • 设备级API:自定义kernel内直接执行put/get/reduce/barrier操作
  • 对称内存:分配对称内存窗口,映射为逻辑端点标识符
  • 16字节对齐:所有源和目标指针必须16字节对齐,任务大小为16的倍数
  • 计数任务:消除传统fence+flag同步,使用用户管理的计数器
  • 跨代理fence:建立不同代理类型间的happens-before关系
  • 共享内存barrier:使用每个CTA一个slot的barrier会话实现团队同步
影响分析: NCCL CFT代表了NVIDIA在集合通信库层面的核心创新。通过将通信操作下沉到设备级API,实现真正的计算-通信并行。这对大规模训练(如Megatron-LM)和推理(如vLLM)的性能优化至关重要。要求CUDA Toolkit 13.3和SM_100架构(Blackwell)。
来源: NCCL CFT官方文档 | NCCL Device API

接近光速延迟的GPU集合通信 (Near Speed-of-Light GPU Collectives)

arXiv:2607.16100 2026 | ETH Zurich / NVIDIA
核心创新: 研究团队开发了专用routine,显著降低小规模数据交换的等待时间,使延迟接近物理硬件最小值。通过消除标准同步barrier、利用共享内存和数据广播技术,扩展NCCL设备级接口构建定制API。对LLM文本生成和传统HPC任务均有显著加速。
技术实现:
  • 消除同步barrier:移除传统集合通信中的全局同步开销
  • 共享内存利用:通过共享内存实现快速数据交换
  • 数据广播:优化广播模式减少点对点通信延迟
  • NCCL设备接口扩展:构建定制API支持对称内存布局优化
  • 接近物理极限:延迟达到硬件互连的理论最小值
影响分析: 该研究由ETH Zurich和NVIDIA联合完成,发表于2026年。对LLM推理中的自回归解码阶段尤为关键,每个token的生成都涉及多次小规模集合通信。接近光速延迟的实现可显著提升推理吞吐量和降低延迟。相关技术已整合入NCCL库。
来源: arXiv:2607.16100

AMD 计算通信并行专利

封装内与封装外混合内存系统 (Combined On-Package and Off-Package Memory)

US20230393788A1 2023-12-07 公开
核心创新: 专用硅层桥接GPU与内部堆叠存储(HBM)和外部模块(DDR),通过聚合不同硬件类型呈现单一统一可寻址空间。智能路由层将访问请求导向本地高速区域或外部高容量区域,后台自动在层级间迁移数据。
技术实现:
  • 智能路由:基础逻辑层directing访问请求,免除主处理器的映射和转换负担
  • 分层池化:资源分为高速本地区域(HBM)和高容量外部区域(DDR)
  • 无缝迁移:系统在后台层级间迁移信息,确保连续运行不中断
  • 交织映射:访问请求同时分布到本地和外部硬件,最大化聚合传输率
  • 统一接口:主机处理器与单一整合内存空间交互
影响分析: 该专利对AMD Instinct MI300/MI350系列APU架构至关重要。通过HBM与外部DDR内存的统一寻址,可在保持高带宽的同时扩展内存容量。MI300X的192GB HBM3统一内存直接受益于此技术,对大模型推理场景中的KV cache扩展有重要意义。
来源: Google Patents - US20230393788A1

并行GPU稀疏矩阵调度 (Parallel GPU Sparse Matrix Scheduling)

AMD Patent 2025 授权
核心创新: AMD开发了针对稀疏矩阵运算的GPU并行调度专利,优化多GPU间的数据分布和计算负载均衡。通过智能分区算法将稀疏矩阵的非零元素均匀分配到多个GPU,减少跨GPU通信开销。结合预计算通信模式,实现计算与通信的流水线重叠。
技术实现:
  • 智能分区:将稀疏矩阵非零元素均匀分配到多GPU
  • 负载均衡:动态监控各GPU计算负载,实时调整分配策略
  • 通信预计算:提前计算通信模式,与计算阶段重叠
  • 流水线重叠:计算与通信采用流水线方式并行执行
  • ROCm集成:深度集成到ROCm软件栈中
影响分析: 该专利对AMD Instinct GPU在大规模稀疏计算场景(如GNN训练、推荐系统)中的性能至关重要。稀疏矩阵是许多AI模型的核心数据结构,优化其并行调度可显著提升训练效率。ROCm生态的集成使该技术在开源社区中具有广泛影响力。
来源: Patentlyze - AMD Parallel GPU Sparse Matrix

UALink 1.0规范 2024年成立 | 2026年白皮书

  • 开放标准,支持多厂商硬件互操作
  • 模块化机架级架构,可整合不同厂商设备
影响分析: UALink是AMD联合Intel、Google等对抗NVIDIA NVLink垄断的核心战略。虽然单连接带宽(800 GB/s)低于NVLink 5.0(1.8 TB/s),但支持近两倍的加速器数量(1024 vs 576),且为开放标准。阿里云和苹果后续加入董事会,预计2026-2027年形成产业生态。

Intel 计算通信并行专利

多GPU内存缓存同步系统 (Multi-GPU Memory Cache-Sync System)

US20260211839A1 2026-07-23 公开
核心创新: 自动化多GPU间的内存缓存协调。采用多tile布局,每个tile拥有独立的内存管理控制器(MMU),主动监控相邻tile的本地存储缓冲区。检测到本地修改后,自主评估是否需要推送更新到远程tile,选择性通过高速通信fabric发送更新,避免过时信息同时节省带宽。
技术实现:
  • 多tile架构:每个segment拥有独立的内存管理控制器(MMU)
  • 主动缓存监控:一个tile的MMU追踪相邻segment的存储内容
  • 选择性刷新:检测到修改后自主判断是否需要更新远程缓存
  • 带宽优化:仅传输变更数据,而非全量刷新
  • 通信fabric:通过高速互连实现跨tile缓存一致性
影响分析: 该专利对Intel Falcon Shores和未来的多tile GPU架构至关重要。自动化缓存同步减少了软件维护一致性的开销,对分布式训练中的梯度同步和推理中的KV cache共享有直接优化作用。这也是Intel对标NVIDIA NVLink缓存一致性技术的关键布局。
来源: Patentlyze - Intel Multi-GPU Cache-Sync

技术实现:

  • UCIe链路:通过Universal Chiplet Interconnect Express实现高速互连
  • 自动修复:内置built-in repair机制提高制造良率
  • 成本优化:消除昂贵的硅中介层,降低封装成本
  • 内存层邻近处理单元:通过垂直通道实现低延迟访问
影响分析: XBM架构代表了Intel对下一代AI加速器内存方案的前瞻布局。通过消除HBM的硅中介层依赖,Intel可在降低封装成本的同时提升内存带宽。UCIe互连标准的支持使该架构具有多厂商兼容性。预计2027-2028年可能在Intel下一代GPU中商用。

趋势展望

1. 内存语义互连成为竞争焦点

NVIDIA NVLink 5.0(1.8 TB/s)、UALink 1.0(800 GB/s但支持1024加速器)、华为HCCS 2.0(400 GB/s)都在向内存语义演进。UALink作为开放标准支持多厂商互操作,直接挑战NVLink的封闭生态。壁仞科技的NPO光互连更是突破传统电互连限制,实现微秒级延迟和动态拓扑重构。未来互连将不再仅仅是数据传输通道,而是共享内存空间的延伸。NVIDIA的多GPU缓存同步专利(US20260211839A1)和内存管理增强专利(US20260349929A1)反映了这一趋势。

来源: UALink联盟 | NVIDIA NVLink | 壁仞NPO光互连

2. 计算通信重叠从软件走向硬件

NCCL CFT的设备级API、FlashOverlap的警报驱动并发、Resource-aware的零代码修改方案表明,计算通信重叠正在从纯软件层面下沉到硬件特性利用。接近光速延迟的集合通信(arXiv:2607.16100)通过消除同步barrier和利用共享内存,将延迟推向物理硬件极限。未来可能出现专用的通信引擎与计算引擎完全并行,实现真正的"零SM占用"通信。

来源: NCCL CFT | FlashOverlap | Resource-aware Overlap | Speed-of-Light Collectives

3. 多Chiplet架构驱动本地化内存设计

NVIDIA的多芯片本地内存路由专利(US20260288335A1)和内存管理增强专利(US20260349929A1)反映了Blackwell及后续架构向多chiplet演进的趋势。将数据本地化到各chiplet的"一致性点"内存,减少跨die通信,成为大规模GPU设计的核心策略。Intel的XBM内存架构(后端晶体管DRAM堆叠)和缓存同步专利(US20260211839A1)专门解决多tile间的一致性问题。这一趋势在AMD MI300(混合内存系统)中同样明显。

来源: NVIDIA Multi-Chip Patent | Intel XBM Architecture | Intel Cache-Sync

4. MoE通信成为新战场

DeepSeek-V3/Qwen 3等超大MoE模型的兴起催生了通信库的激烈竞争。NVIDIA Hybrid-EP比DeepEP快14%,UEP(OSDI 2026)通过CPU代理实现跨硬件兼容,Occult(ICML 2025)通过协作通信减少40%+运行时开销,Lagom提出自适应流水线优化。Tile级MoE重叠(arXiv:2607.19539)代表了从chunk级向更细粒度演进的趋势。MoE的all-to-all通信模式与传统AllReduce不同,需要专门的优化策略,这一领域预计将持续快速发展。

来源: NVIDIA Hybrid-EP | Occult ICML'25 | Lagom | Tile-Level MoE Overlap

5. 编译器自动化重叠成为主流
