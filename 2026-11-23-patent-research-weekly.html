芯片间数据链路公平性修复 (Bandwidth Allocation in Interconnects)

US2026/0361665 A1 2026-11-12 公开 | 申请 19/113,282 (2025-05-12)
核心创新: 面向NVLink/C2C等芯片间互连的带宽公平分配机制——双阶段选择+中间容量检查,防止单一"话痨"发送端独占共享传输许可池,确保小请求不被大传输无限阻塞。
技术实现:
  • 双阶段仲裁机制:第一阶段预留基线带宽配额,第二阶段按容量检查动态分配剩余
  • 基线配额按最大数据块尺寸设计,保证小粒度请求不被饿死
  • 明确覆盖GPU-GPU、GPU-NIC、GPU-NVSwitch等互连场景
  • 发明人:Naveen Kumar Narrishetti、Sathyanarayan Balaji、Kiran Kumar Muralidharan
  • 解决多dielet/multi-GPU系统中credit-based flow control的公平性问题
影响分析: NVLink 6将机架级互连带宽推至260 TB/s,多GPU/多die共享同一物理链路时公平性直接决定尾部延迟。此专利为Vera Rubin NVL72的72-GPU全互连域提供QoS基础保障。
来源: Patentlyze - NVIDIA Fairness Fix for Chip-to-Chip Data Links

US2026/0350353 A1 2026-11-05 公开 | 申请 2025-05-01
核心创新: 将LLM推理的长上下文KV cache跨多处理器分区存储,各芯片计算本地分片后经"更宽分布"方式交换中间结果,消除单卡内存瓶颈对长对话的限制。
技术实现:
  • 长输入序列的注意力状态按策略切分到多块GPU的本地HBM
  • 各GPU独立计算本地分片产生中间激活值
  • 经NVLink/NVSwitch执行all-gather式"更宽分布"汇聚结果
  • 第二阶段(如FFN)采用与第一阶段不同的分布策略
  • 发明人:Nidhi Bhatia、Ankit More
  • 与US2026/0133908A1(动态KV cache调度)形成互补:前者管层级,后者管位置
影响分析: 直接支撑Vera Rubin NVL72的130 TB/s NVLink域内长上下文推理。当模型上下文超过单卡288GB HBM时,跨芯片分区是唯一可行路线,此专利卡位了分区+汇聚的具体实现方式。
来源: Patentlyze - NVIDIA Splitting AI Memory Across Many Chips

NCCL 2.28: 通信-计算融合与Copy Engine集合通信 (Device API & CE Collectives)

NCCL 2.28 官方技术博客 2026-11 发布
核心创新: NCCL 2.28引入三大能力:①GPU内核直接发起通信(Device API)消除host-side延迟;②Copy Engine(CE)执行集合通信释放SM计算资源;③Multimem硬件多播实现最高780 GB/s NVLink带宽利用率。
技术实现:
  • Device API (GIN): GPU Initiated Networking——内核直接管理网络传输,无需CPU介入,消除host-launch延迟
  • CE Collectives: 专用Copy Engine硬件执行数据搬运与归约,SM完全释放给计算kernel
  • Multimem: NVLink硬件多播,单条写操作广播到多GPU,CE Multicast实测达~780 GB/s
  • LSA (Load/Store Accessible): 跨GPU PCIe内存直接load/store访问
  • 新增always-on性能分析工具,追踪独立网络上下文与事件trace
  • 支持native host scatter命令、batched symmetric执行
影响分析: NCCL 2.28标志着"通信卸载到专用引擎"路线的全面落地——CE Collectives让SM 100%用于计算,GPU-initiated networking让CPU退出通信关键路径。这与AMD RCCL GPU-initiated SDMA形成正面竞争。
来源: NVIDIA官方技术博客 - NCCL 2.28 Fusing Communication and Compute

多芯片GPU本地内存路由 (Multi-Chip GPU Local Memory Routing)

US2026/0288335 A1 2026-09-24 公开 | 申请 2025-03-21
核心创新: 多die GPU中每个die管理独立屏幕区域,配置参数存入本地"一致性点"内存,避免跨die广播;粗粒度交织虚拟内存将地址空间按大块分配给各die,芯片间桥接仅在必要时激活。
技术实现:
  • 分段渲染:每个die负责独立矩形区域,配置参数写入本地point of coherence内存
  • 版本缓冲区、线程数据限制在本地die,不跨die广播
  • 粗粒度交织虚拟内存:大尺寸交替块分配给各die
  • 芯片间桥接仅在跨die访问时激活,大幅降低延迟、节省带宽
  • 发明人: Ziyad Hakura、Karim Abdalla、Andrei Khodakovsky、Eric Werness
影响分析: 直接服务Blackwell双die及Rubin多die封装架构。本地路由+按需跨die的内存访问模式,是解决多die GPU"静默性能杀手"的关键专利。
来源: Patentlyze - NVIDIA Multi-Chip GPU Local Memory Routing

TokenWeave: 高效计算-通信重叠的分布式LLM推理 (Microsoft Research, MLSys 2026)

MLSys 2026 Oral Microsoft Research | arXiv:2505.11329
核心创新: 面向TP推理(低至1024 token序列)的计算-通信重叠方案。设计联合AllReduce-RMSNorm kernel,利用NVSHARP/Multimem硬件特性,仅占2-8个SM即完成通信与归一化的并行执行。
技术方案:
  • 联合AllReduce-RMSNorm kernel:通信与归一化在同一kernel中并行
  • 利用NVSHARP(网内归约)和Multimem(硬件多播)硬件特性
  • 仅消耗2-8个SM(8-GPU配置),计算资源几乎无损
  • 性能:延迟降低1.28x,吞吐提升1.19x
  • 在某些场景下甚至超过"完全消除通信"的理论上限

CCCL: GPU内压缩耦合集合通信 (In-GPU Compression-Coupled Collective Communication)

arXiv:2604.17172 多机构联合 | 2026-04
核心创新: 在GPU集合通信库中内置压缩引擎(CCCL-core),利用浮点指数的可预测性隔离编码,将压缩-传输-解压融合在单一warp级处理中,无需用户端任何修改。
技术方案:
  • CCCL-core引擎:隔离浮点指数位并编码,局部频率表替代全局映射
  • 内存读取从3次pass降为1次pass
  • warp级融合:压缩+网络传输+解压在同一处理环境完成
  • 仅对远程网络流量应用归约算法,忽略芯片内传输避免额外开销
  • 性能:数据压缩率最高70%,NVLink带宽利用率达3x,微基准吞吐提升30%
  • vLLM参数解聚场景:端到端速度提升最高10.1%
  • 替换可执行文件即可启用,零代码修改
来源: arXiv:2604.17172 论文原文

Resource-aware Computation-Communication Overlap for multi-GPU ML Workloads (ISC 2026 AI on HPC Workshop)

技术方案:
  • 共享内存管理:为每个SM动态分配/保留通信所需的shared memory

  • 跨硬件验证:NVIDIA A40、A100、H100、AMD MI250X
  • 性能:端到端执行时间最高减少25.5%
  • 关键优势:无需修改NCCL/RCCL等厂商库或kernel实现

趋势展望

1. 通信卸载进入"硅级"时代: CE/SDMA/DMA引擎全面替代SM

本周最显著的产业信号:NVIDIA NCCL 2.28的CE Collectives让Copy Engine硬件执行集合通信(释放SM 100%用于计算),AMD MI455X引入专用DMA引擎+Tensor Data Mover异步拷贝,RCCL GPU-initiated SDMA让1个CU达到64 CU带宽。三家(含Intel Gaudi 3 NIC内张量引擎)不约而同将通信从"占用计算资源"转向"专用硬件执行"。CCCL论文进一步证明:压缩-传输-解压可在warp级融合,NVLink带宽利用率达3x。2027年通信库的竞争力将取决于专用引擎的硅面积投入。

来源: NCCL 2.28官方 | MI455X Hot Chips | CCCL论文

2. NVLink 6 vs UALoE: 机架级互连的开放与封闭之争白热化

NVIDIA NVLink 6实现3.6 TB/s/GPU、260 TB/s机架、130 TFLOPS网内计算,配合NVLink Fusion允许定制XPU接入(封闭生态的开放姿态);AMD MI455X以UALoE 1.8 TB/s/GPU对标,72-GPU Helios机架260 TB/s scale-up。两条路线的带宽差距从NVLink 5时代的2x缩小到NVLink 6的2x。Intel加入UAL联盟并申请跨GPU屏障专利(US20260195292A1),Gaudi 3走"以太网scale-up"差异化路线(24x200GbE RoCE v2)。机架级互连标准之争将在2027年进入采购决策期。

来源: NVIDIA NVLink 6官方 | AMD MI455X路线图 | Intel UAL barrier专利

3. 分布式内存管理成为LLM推理的核心战场

本周NVIDIA有两项直接相关的专利公开:US2026/0350353A1(跨芯片分布式KV cache分区)和US2026/0361665A1(互连带宽公平分配),加上此前的US2026/0133908A1(动态KV cache层级调度)和US2026/0288335A1(多die本地内存路由),形成完整的"分布式推理内存管理"专利组合。当模型上下文超过单卡288GB HBM时,KV cache的分区、调度、汇聚、公平性成为推理性能的决定因素。TokenWeave(MLSys 2026 Oral)从软件层证明联合AllReduce-RMSNorm可在低至1024 token时实现1.28x延迟降低——硬件专利+软件系统共同卡位。

来源: US2026/0350353A1 | US2026/0361665A1 | TokenWeave MLSys 2026

4. 国产GPU专利布局加速: 从单点突破到体系化覆盖

5. 压缩感知通信: 从"更快传输"到"更少传输"

CCCL(arXiv:2604.17172)代表一个新方向:不追求"更快地传输",而是"传输更少的数据"。利用浮点指数的可预测性隔离编码,warp级融合压缩-传输-解压,实现70%数据压缩+3x NVLink带宽利用率+零代码修改。当互连带宽增速放缓(_nvlink 6的3.6 TB/s已是铜缆物理极限级别),压缩感知通信可能成为突破"内存墙"的第二条路线,与NVIDIA的NVFP4量化(权重省3.5x)、压缩显存API(US2026/0149822A1)形成完整的"数据瘦身"专利栈。

来源: CCCL论文 | NVIDIA压缩显存API

6. 自适应重叠: 从静态配置走向运行时感知

Resource-aware论文(arXiv:2606.09200, ISC 2026 Workshop)和ACM SIGARCH 2026的"Efficient and Adaptable Overlapping"共同指向:未来的计算-通信重叠不再是编译时静态配置,而是运行时根据SM负载、共享内存使用、网络拥塞动态调整。Resource-aware方案在A40/A100/H100/MI250X上实现最高25.5%加速且无需修改厂商库——这意味着重叠优化正在从"专家手工调优"走向"框架自动适配",大幅降低大规模训练的部署门槛。
