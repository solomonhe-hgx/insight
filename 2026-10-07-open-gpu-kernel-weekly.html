nvidia-uvm: propagate EGM DMA mapping failures PR NEW

PR #1423 2026-10-06 | Open
改进内容: 从 uvm_gpu_map_cpu_pages_for_egm() 返回记录的状态，而不是无条件报告 NV_OK。这样传播 DMA 链路和同步失败，并恢复调用者的 NV_ERR_NOT_SUPPORTED 回退机制。

代码变更: 269 行新增, 1 行删除, 2 个文件

关键改进:

  • 错误传播：DMA 链路和同步失败不再被隐藏
  • 回退机制：恢复 NV_ERR_NOT_SUPPORTED 处理
  • 回归测试：添加主机回归测试验证错误传播
来源: GitHub PR #1423

  • ATS region flush 优化
  • 通道选择算法改进

模式: Vulkan 工作负载似乎更容易触发

短期与中期趋势

短期趋势 (1-2 周)

  • VA 空间管理修复: 预计将有针对 dmaAllocMapping_GM107 VA exhaustion 的补丁提交
  • UVM TLB 优化合并: PR #1375 的 TLB batch coalescing 优化可能在后续版本中被采纳
  • B300 HGX 稳定性: Xid 145 问题需要 NVIDIA 发布 Fabric 管理固件更新

中期趋势 (1-3 月)

  • 开源驱动成熟度: Arch Linux 默认采用 nvidia-open 标志着开源驱动进入生产环境主流
  • Grace 平台生态: NVLink C2C 在 Grace-Blackwell 平台的软件支持将逐步完善
  • MMU 错误处理增强: PR #1423 的 EGM DMA mapping 错误传播机制将成为标准

核心洞察

1. 开源驱动进入主流发行版

Arch Linux 将 nvidia-open 设为默认，标志着开源驱动在稳定性和功能上已达到生产环境要求。这将加速社区反馈循环，推动更快的问题修复。

2. VA 空间管理成为痛点

多个 Issue 指向 BAR1 VA 空间耗尽问题，特别是在 Wayland/Hyprland 环境下。这表明随着多显示器和高DPI普及，VA 空间管理算法需要优化。

3. B300 HGX 生产环境稳定性待提升

Xid 145 Fabric-wide 错误影响 AI 训练任务，需要 NVIDIA 在固件和驱动层面协同解决。开源驱动的问题追踪有助于提高透明度。

4. UVM 子系统活跃开发

本周 5 个 UVM PR 显示该子系统正在积极优化，包括 TLB batch 合并、错误处理增强、构建兼容性修复等，这些改进将提升内存管理效率。
